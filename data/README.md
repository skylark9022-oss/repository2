# data/ 폴더 규칙

| 폴더 | 내용 | 깃 추적 | 수정 |
|---|---|---|---|
| `raw/` | 내려받은 원본 파일 그대로 | 추적 (단, 파일당 100 MB 미만만) | **금지** |
| `interim/` | 원본을 읽어 표 형태로만 바꾼 중간 파일 | 일부 제외 (`.parquet`, `.pkl`) | 코드로 재생성 |
| `processed/` | 통합 스키마 (`docs/schema.md`) 로 정리된 DB | 추적 | 코드로 재생성 |
| `external/` | 핵종 자료가 아닌 보조 자료 (WOA 기후값 등) | 대용량 제외 | 받는 방법만 기록 |

## raw/ 하위 구조

출처별로 폴더를 나눕니다.

```
raw/
├── maris/            ← IAEA MARiS 에서 받은 파일
│   ├── README.md     ← 받은 날짜, URL, 검색 조건, 라이선스
│   └── <원본파일>
├── ham/              ← HAM database (Aoyama & Hirose)
└── ...
```

각 출처 폴더에 `README.md` 를 두고 **입수 조건**을 반드시 적습니다.
같은 DB 라도 검색 조건이 다르면 결과가 달라지므로, 나중에 재현하려면 조건 기록이 필수입니다.

## 깃 용량 주의

- GitHub 는 파일 하나가 100 MB 를 넘으면 푸시를 거부합니다.
- 50 MB 를 넘으면 경고를 냅니다.
- 큰 파일은 `.gitignore` 에 추가하고 `README.md` 에 받는 방법을 적어 두는 것으로 대신합니다.
  (Git LFS 라는 대안도 있으나, 처음에는 쓰지 않는 것을 권장합니다.)
